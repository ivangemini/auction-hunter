# Analytics Schema v1

## Transport boundary
Gameplay emits typed analytics through `trackEvent()` in `src/analytics.ts`. Every event is wrapped with:

- `schemaVersion` — currently `1`;
- `eventName` — stable snake-case event name;
- `eventId` — per-event random ID;
- `sessionId` — stable for the current page session;
- `sequence` — monotonically increasing within the page session;
- `occurredAt` — ISO timestamp;
- `payload` — event-specific typed data.

The core does not depend on an analytics vendor. Consumers can either register a sink with `registerAnalyticsSink()` or listen for the browser `auction-hunter:analytics` CustomEvent. A future Yandex/Metrica adapter can therefore be added without changing domain events.

## Monetization telemetry
Rewarded events include the summary placement and exact cash reward. The close event records whether an impression opened, whether `onRewarded` occurred and the final adapter outcome.

Interstitial request/close events include the auction number, whether Yandex actually showed an impression and the final adapter outcome. These events are additive schema-v1 fields and do not expose personal identifiers.

## Currently wired events
Session start, onboarding completion, auction start/win, Daily completion, sell/keep decisions, collection-set reward claims and monetization events are emitted today. Other typed gameplay events remain part of the stable contract for the next instrumentation pass.

## Privacy
The schema intentionally contains no names, email addresses, device identifiers, free-form user text or other direct personal identifiers. Session/event IDs are ephemeral random IDs generated by the game.

## Versioning rule
Additive optional payload fields and additive event names may remain in schema v1. Renaming/removing events, changing field meaning, or making an incompatible payload change requires a new schema version.
