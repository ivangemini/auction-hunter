# Analytics Schema v1

## Transport boundary
Gameplay emits typed analytics through `trackEvent()` in `src/analytics.ts`. Every event is wrapped with:

- `schemaVersion` — currently `1`;
- `eventName` — stable snake-case event name;
- `eventId` — per-event random ID;
- `sessionId` — stable for the current page session;
- `sequence` — monotonically increasing within the page session;
- `occurredAt` — ISO timestamp;
- `payload` — event-specific typed data.

The core does not depend on an analytics vendor. Consumers can either register a sink with `registerAnalyticsSink()` or listen for the browser `auction-hunter:analytics` CustomEvent. A future Yandex/Metrica adapter can therefore be added without changing domain events.

## Rewarded-ad funnel
The first monetization placement uses `round_summary_cash` and records:
- the requested reward and final bid when the player opts in;
- the SDK result (`rewarded`, `closed`, `unavailable`, `error`);
- the actual cash grant separately when `onRewarded` is confirmed.

Separating SDK result from the economy mutation lets analysis detect callback/reward mismatches and measure opt-in/completion without inferring grants from UI state.

## Currently wired events
The integration currently emits session start, onboarding completion, auction start/win, Daily completion, sell/keep decisions, collection-set reward claims and the rewarded-ad funnel. The remaining typed events define the contract for the next instrumentation pass and can be wired without changing the schema.

## Privacy
The schema intentionally contains no names, email addresses, device identifiers, free-form user text or other direct personal identifiers. Session/event IDs are ephemeral random IDs generated by the game.

## Versioning rule
Additive event names and optional payload fields may remain in schema v1. Renaming/removing events, changing field meaning, or making an incompatible payload change requires a new schema version.
